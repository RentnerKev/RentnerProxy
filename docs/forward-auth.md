# Forward Auth access policies

Forward Auth is available in the current Beta 1 development code and `:dev` image after that image is rebuilt from `main`. The pinned `v1.0.0-alpha.6` image does not include it. It uses Caddy's built-in [forward-auth pattern](https://caddyserver.com/docs/caddyfile/directives/forward_auth) through typed JSON; RentnerProxy does not run an identity provider.

## Configure a policy

In **Access Policies**, choose **Authenticated** with **Forward Auth**, or **Combined** with IP rules and **all** checks required. Select a provider preset to fill suggested response headers, then set the gateway's full check URL. The provider choice is descriptive and does not alter the underlying Caddy implementation. Assign the policy to a proxy host. Use a separate policy for a different gateway or identity-header contract.

The endpoint must be a canonical `http://` or `https://` URL with a path. Credentials, query strings, fragments, placeholders, and encoded path bytes are rejected. A timeout from 1 to 30 seconds bounds the dial and response. HTTPS always verifies the gateway certificate with system trust. A custom CA and disabled TLS verification are not offered for Forward Auth; install a trusted CA in the appliance environment if the gateway uses a private issuer. Internal HTTP endpoints are allowed for an administrator-controlled private network. The setting is a server-side request destination, so only administrators with policy-edit rights should configure it. Never place tokens in the URL.

The optional **gateway path prefix** publishes one narrow path on the protected host directly to the same auth service before the auth check. This is needed for a provider's login callback and static paths. For example, `/outpost.goauthentik.io/` covers that exact subtree. Do not use a path that overlaps protected application content. The prefix is intentionally public, and the auth service must enforce its own callback and state checks.

## Request and failure behavior

The route order is: ACME challenge, optional CrowdSec, HTTPS redirect, optional public gateway prefix, IP check for a combined `all` policy, Forward Auth, request body limit, then application. Basic Auth and Forward Auth cannot be active together. The `any` IP combination cannot be used with Forward Auth because it would permit an IP match to skip the gateway. CrowdSec's Local API outage remains fail open as documented separately; a Forward Auth outage is fail closed.

Caddy sends a GET precheck to the exact configured path. It rebuilds the auth request headers, sending the original host as `X-Forwarded-Host`, original URI and method metadata, effective client IP, and the original scheme derived from the existing trusted-proxy configuration. HTTPS gateways use their own DNS name for HTTP Host and TLS server name; HTTP gateways retain the application Host. Cookie and Authorization are optional request-header selections; Cookie is the default. It never forwards arbitrary client headers to the auth check. If Caddy receives a 2xx response, it copies only the configured nonempty identity response headers into the application request, removing any client-supplied values first. It also removes Authorization from the application request. The ordinary Cookie header still reaches the application, so configure the application to handle its own cookies appropriately.

Any non-2xx gateway response, including 401, 403, and 3xx, goes back to the client without calling the application. Redirects are passed through; Caddy does not follow them in the precheck. A timeout, refused connection, or TLS validation failure produces a proxy error and cannot grant access. Access logs remove request headers and query values under the existing logging rules. Policy edits are audited by changed field name rather than by request or response values. The Security Dashboard shows the number of policies configured for Forward Auth and their providers; it does not probe the gateways or assert health.

Set `RENTNERPROXY_PROXY_TRUSTED_PROXY_CIDRS` only to direct proxy peers that you control. With no trusted peer, the auth gateway receives Caddy's directly observed client address and listener scheme. If a trusted proxy terminates HTTPS before Caddy, use the existing strict `X-Forwarded-Proto: https` contract. Client-supplied `X-Forwarded-For`, `X-Real-IP`, `Forwarded`, and `X-Forwarded-Proto` are never accepted as unqualified identity. See [architecture](../ARCHITECTURE.md#certificate-and-trust-boundaries).

## Provider setup

| Provider                                                                                  | Check endpoint path                  | Suggested response headers                                                  | Login path                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Authentik](https://docs.goauthentik.io/add-secure-apps/providers/proxy/server_caddy/)    | `/outpost.goauthentik.io/auth/caddy` | `X-Authentik-Username`, `X-Authentik-Email`                                 | Set gateway prefix `/outpost.goauthentik.io/`; the outpost handles login and callback requests.                                                                                                                             |
| [Authelia](https://www.authelia.com/integration/proxies/caddy/)                           | `/api/authz/forward-auth`            | `Remote-User`, `Remote-Email`                                               | Authelia's authorization response directs the browser to its configured portal.                                                                                                                                             |
| [oauth2-proxy](https://oauth2-proxy.github.io/oauth2-proxy/7.6.x/configuration/overview/) | `/oauth2/auth`                       | Only headers enabled by `--set-xauthrequest`, such as `X-Auth-Request-User` | A 401 from `/oauth2/auth` stays a 401. Arrange a login entrypoint in the application or gateway; the preset does not invent a redirect. If serving `/oauth2/*` on the protected host, set `/oauth2/` as the gateway prefix. |

For Authentik, configure a proxy provider and outpost for the exact protected host, and point the policy to the reachable outpost URL, for example `http://authentik:9000/outpost.goauthentik.io/auth/caddy`. Set the gateway prefix shown above. The outpost must be able to build correct public redirects; configure its external host and trusted proxy settings per Authentik's guide. Only select the identity headers your application actually trusts.

For Authelia, configure its access-control policy, session and portal URL, then use its forward-auth endpoint, for example `https://auth.example.com/api/authz/forward-auth`. Configure trusted proxies on the Authelia side to match the network path from Caddy. Its 2xx and deny/redirect responses follow the generic contract above.

For oauth2-proxy, ensure its auth endpoint and cookie domain work for the protected host. Enable `--set-xauthrequest` if identity headers are needed. The endpoint's [documented 202/401 behavior](https://oauth2-proxy.github.io/oauth2-proxy/7.6.x/configuration/overview/) is compatible with the generic check, while its full interactive login flow depends on the surrounding application or gateway configuration.

The repository tests exercise these HTTP contracts with a local auth fixture and real Caddy in Production Smokes. They do not run full Authentik, Authelia, or oauth2-proxy deployments. Treat each live-provider setup as an integration test for the target network, cookies, redirects, and proxy trust before relying on it in production.
